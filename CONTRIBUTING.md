## Contributing Code of Conducts
Hey there, here is our code of conducts:

### Basic Things to Know
* This repo is licensed under [*GNU GENERAL PUBLIC LICENSE  Version 3*](./LICENSE), your code submitted should be
compatible with this license.
* Please use English if you're writing your commit message.
* If you're on GitHub, please also use English if you're posting a merge request/issue so that everyone could read it.
* Merge requests will be rejected if the `MR checker` (which automatically runs when you open a merge request) fails. 
You may want to run `./mr-test` locally before opening a merge request.

### AI Policy
We accept AI-generated codes with these restrictions:
* It needs to be compatible w/ [*GNU GENERAL PUBLIC LICENSE  Version 3*](./LICENSE) -- please be careful if you are
asking AI to port something here.
* All `MR checker` things still apply.
* You'll need to fully understand what the AI did and the reason of why it used this way to resolve the merge requestoblem.
* You'll be responsible for the AI generated contents.

### Issues
#### Title
we use prefix for the issue title, here is the list of prefix preferred:
- **suggestion**: Your suggestion to `ptre`.
- **question**: Asking an question.
- **bug**: A bug you found.
- **featreq**: Requiring new feature(s).

Here are some examples:
```
suggestion: Improving the issue title
question: Does ptre suppot Windows?
bug: Auto completion failed on XXXX
featreq: Consider adding AmberPM packaging
```

#### Content
* Please do not post duplicate issues.
* Please only mention one things in the issue.
* We regularly check the issues page, so please do not @mention maintainers in issues urge progress.

### Merge Requests
> Merge requests prior to Mon, 28 Sep 2026 12:41:00 -0500 are unaffected by these rules.

* Please open an issue first before posting the merge requests if you do not have direct write access to the repository. We may directly close the merge request if they're not linked to an issue. Please mention issue number in the merge requests descriptions. e.g. `This merge request would closes (GitHub) #1234.`
* If you do have the direct write access to the repository, we encourage you to also post a merge request for each feature.
For those `chore` commits, you can write to `main` branch directly.
* Please do not post large merge requests if unnecessary.
* Each merge request will trig a merge requests, a merge requests have to pass all the tests.
* All commit messages will be needed to be written in simple English with prefixes such as `chore:`, `feat:`, `add:`, `create`.
* You agree to license or re-license the code you submit under the GNU General Public License Version 3.
* We do not object to the use of AI; however, while we permit it, we do not want "AI slop." You need to understand the 
rationale behind every change you make; if the description of a merge request appears to be entirely AI-generated, the 
request will be closed.
